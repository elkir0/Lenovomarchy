the mobile ones unless they are held (its `omamobile-update` does that).

## Upgrade done on the tablet (2026-11-17 afternoon)

Order followed, each step first rehearsed in the container
`lenovomarchy-rootfs:aarch64` (`out/rehearsal/`, not in git):

1. Backup on the tablet: `/root/backup-20261117/` (Omarchy and mobile
   files before the change, user configuration, the 4.0.6 packages, the
   migration logs).
2. `omamobile-omarchy` 0.1.48-1 and `omamobile-shell` 0.2.133-1 (built by
   `image/tools/build-pkg` from `image/pkg/`) on Omarchy 4.0.6: 24
   patches applied and verified. Home screen, quick settings and the lock
   glance view checked by screenshot.
3. `omamobile-shell` 0.2.133-2: the first build left phone steps in
   `omamobile-setup-user` (a mobile-network plugin entry, GNSS and
   fingerprint probes, a voice import). After -2 the shell log has none
   of them.
4. `omarchy` and `omarchy-settings` 4.5.0-3 plus `omarchy-speedtest`
   0.2.1-1 (sha256 as pinned by Omarchy Mobile, signatures good against
   `omarchy-keyring`), `IgnorePkg` lifted for the transaction only: the
   hook applied the 24 patches of the 4.5 series.
5. `yt11-omarchy-migrations-hold` held 25 of the 98 pending migrations
   (`image/rootfs/omarchy-migrations.hold`, reasons in
   `M3-MIGRATIONS.md`); `omarchy-migrate` ran the other 73 with exit 0
   and none is pending. Run it from the user's home: from `/root` one
   migration's `find` fails on the working directory.
6. Reboot: no failed user unit, Wi-Fi connected, both cameras listed and
   capturing, `omacam` starts, scale 1.6 and rotation kept.

Found after the reboot:

- `mako` took `org.freedesktop.Notifications` by D-Bus activation two
  seconds before the shell asked for it, so the shell showed nothing.
  Omarchy 4.5 no longer uses mako: removed from the tablet (to remove
  from `image/rootfs/packages.extra`). After that a `notify-send` shows
  as a toast, in the bar badge and in the shade.
- `ufw.service` is failed: `ip6tables-restore` rejects rules in
  `/etc/ufw/before6.rules` because the kernel lacks
  `NETFILTER_XT_MATCH_LIMIT`, `NETFILTER_XT_MATCH_HL`, `IP6_NF_MATCH_RT`
  and `IP6_NF_MATCH_HL`. The IPv4 rules are loaded (INPUT policy DROP,
  SSH on usb0 allowed). `/etc/ufw` dates from the image build
  (2026-11-15), so this is not from the upgrade; whether earlier boots
  failed the same way is not established (their journal has no ufw
  lines). Open.

Not tested: unlocking with the keypad (no way to inject a swipe), the
app drawer and task switcher gestures, the back gesture, the menu, an
`omarchy update` run, suspend from the new shell.

Still to do in the image build: pins for 4.5.0-3, the packages built from
`image/pkg/` instead of the prebuilt archives, the hold list, no mako,
omacam and its dependencies.
